> 🚀 **تازه پروژه را گرفته‌اید؟** فایل [`SETUP-CHECKLIST.md`](./SETUP-CHECKLIST.md)
> یک چک‌لیست قدم‌به‌قدم از راه‌اندازی تا انتشار است.

پیش‌نیاز: **Node.js 22** و **Docker**

```bash
node -v   # باید v22 باشد
```

اگر نسخه‌ات قدیمی‌تر است، بخش [ارتقای Node](#ارتقای-node) را ببین.

```bash
cp .env.example .env # ساخت فایل تنظیمات
npm run setup        # بالا آوردن دیتابیس + مایگریشن + داده‌ی اولیه
npm run dev          # اجرا
```

> به دیتابیس خودت تغییر بده و به‌جای `npm run setup` این‌ها را بزن:
> `npx prisma migrate deploy && npm run db:seed`

## اگر به مشکل خوردی

### ارتقای Node

Tailwind 4 حداقل Node 20 می‌خواهد و درایور SQL Server (برای مهاجرت دیتای اپ قبلی)
Node 22. پس روی **Node 22** برو.

```bash
# نصب nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
exec $SHELL          # ترمینال را دوباره بخوان

nvm install 22
nvm alias default 22 # از این به بعد پیش‌فرض
node -v              # باید v22.x باشد
```

بعد از ارتقا، حتماً یک نصب تمیز بزن (باینری‌های نیتیو برای نسخه‌ی Node قبلی ساخته شده‌اند):

```bash
rm -rf node_modules
npm ci
```

> داخل پوشه‌ی پروژه `nvm use` هم کافی است — نسخه از `.nvmrc` خوانده می‌شود.

### همه‌ی روزها می‌گویند «وقت خالی ندارد»

این را بزن، خودش علت را می‌گوید:

```bash
npm run doctor
```

معمولاً یکی از این چهارتاست:

1. **آن پرسنل برنامه‌ی هفتگی ندارد** — شایع‌ترین علت. پرسنلی که تازه از پنل
   اضافه می‌شود تا وقتی برنامه‌ی هفتگی‌اش ثبت نشود، در رزرو آنلاین اصلاً
   وقت نشان نمی‌دهد. پنل ← پرسنل ← برنامه‌ی هفتگی
2. **آن خدمت به هیچ پرسنلی وصل نیست** — در پنل ← خدمات، کنارش هشدار
   «پرسنلِ آماده ندارد» می‌بینی
3. **آن روز تعطیل است** — پنل ← تنظیمات ← ساعات کاری (جمعه پیش‌فرض تعطیل است)
4. **امروز را زده‌ای و دیر است** — پیش‌فرض این است که نوبت باید حداقل
   ۳ ساعت جلوتر باشد؛ از پنل ← تنظیمات قابل تغییر است

### `Cannot find native binding` هنگام `npm run dev`

باگ شناخته‌شده‌ی npm در نصب وابستگی‌های اختیاری است
([npm/cli#4828](https://github.com/npm/cli/issues/4828)) — ربطی به کد ندارد.
Tailwind 4 یک باینری نیتیو دارد که npm گاهی نصبش نمی‌کند.

```bash
# مک / لینوکس
rm -rf node_modules
npm ci
```

```powershell
# ویندوز (PowerShell)
Remove-Item -Recurse -Force node_modules
npm ci
```

`npm ci` را ترجیح بده به `npm install`؛ لاک‌فایل باینری همه‌ی پلتفرم‌ها را دارد
و نصب تمیز نسخه‌ی درست را برمی‌دارد. اگر باز هم نشد:

```bash
rm -rf node_modules package-lock.json && npm install
```

> **اول از همه `node -v` را چک کن.** روی Node 18 یا پایین‌تر، Tailwind 4 اصلاً
> اجرا نمی‌شود و دقیقاً همین خطا را می‌دهد — بخش [ارتقای Node](#ارتقای-node).

### `npm run setup` گیر می‌کند یا خطای اتصال به دیتابیس می‌دهد

یعنی Docker بالا نیست. Docker Desktop را اجرا کن و دوباره امتحان کن.
اگر داکر نداری ولی PostgreSQL روی سیستمت نصب است، `DATABASE_URL` را در `.env`
به دیتابیس خودت تغییر بده و به‌جای `setup` این‌ها را بزن:

```bash
npx prisma migrate deploy && npm run db:seed
```

### پورت ۳۰۰۰ اشغال است

```bash
npm run dev -- -p 3001
```

### حساب مشتری (`/login`)

مشتری با شماره موبایل و کد پیامکی وارد می‌شود (بدون رمز عبور) و می‌بیند:
نوبت‌های پیش‌رو، تاریخچه، پرونده‌ی درمانی (با عکس قبل/بعد)، دوره‌های فعال،
رضایت‌نامه‌های امضاشده، پرداخت‌ها و اطلاعات شخصی.
لغو نوبت تا ۶ ساعت قبل و پرداخت بیعانه‌ی آنلاین هم از همین‌جا انجام می‌شود.

### پنل مدیریت (`/admin`)

- **داشبورد** — نوبت‌های امروز، در انتظار تأیید، تعداد مشتریان، درآمد ۳۰ روز، نمودار ۱۴ روزه
- **نوبت‌ها** — جستجو، فیلتر (امروز / پیش‌رو / وضعیت)، تغییر وضعیت، حذف، صفحه‌بندی
- **مشتریان** — جستجو، پرونده‌ی کامل هر مشتری (نوبت‌ها، سوابق درمان، پکیج‌ها،
  رضایت‌نامه‌ها، عکس قبل/بعد، پرداخت‌ها)، یادداشت، محدودسازی
- **رضایت‌نامه‌ها** — نوشتن متن رضایت‌نامه و گرفتن امضا در پرونده‌ی مشتری
- **خدمات** — ویرایش قیمت و مدت، فعال/غیرفعال، افزودن به منتخب
- **پرسنل** — برنامه‌ی هفتگی، خدمات هر نفر، فعال/غیرفعال
- **گالری / مجله / نظرات / پیام‌ها** — انتشار، پنهان‌سازی، حذف
- **پرداخت‌ها** — همه‌ی تراکنش‌های نقدی، کارت‌خوان و آنلاین
- **حقوق و دستمزد** — حقوق پایه + پورسانت، فیش ماهانه با پاداش و کسورات
- **گزارش‌ها** — درآمد، عملکرد پرسنل، پرترددترین روزها و ساعت‌ها، نرخ عدم
  مراجعه، مشتریان بازگشتی و برتر، با خروجی اکسل
- **هزینه‌ها** — دفتر هزینه با دسته‌بندی (اجاره، حقوق، مواد، قبوض...)
- **انبار مواد** — موجودی، خرید و مصرف، هشدار کمبود و بهای تمام‌شده
- **لیست انتظار** — کسانی که وقت دلخواهشان خالی نبوده؛ با یک دکمه پیامک
  «وقت خالی شد» برایشان می‌رود
- **کد تخفیف** — ساخت کد درصدی یا مبلغ ثابت با سقف، بازه‌ی زمانی و ظرفیت
- **نظر مشتری‌ها** — نظرسنجی پس از هر مراجعه، رسیدگی به نارضایتی‌ها و
  انتشار نظرهای خوب در سایت
- **کاربران** — ساخت حساب برای منشی و اپراتور و اتصال حساب به پرسنل
- **پیامک و ایمیل** — گزارش همه‌ی ارسال‌ها
- **تنظیمات** — اطلاعات تماس، شبکه‌های اجتماعی، ساعات کاری، قوانین رزرو، درصد بیعانه

#### نقش‌ها و دسترسی‌ها

| نقش | دسترسی |
|---|---|
| **مدیر کل** | همه‌چیز، شامل حقوق و مدیریت کاربران |
| **مدیر** | همه‌چیز به‌جز ساخت و حذف حساب کاربری |
| **منشی / پذیرش** | نوبت‌ها، مشتریان و پیام‌ها. محتوای سایت و حقوق را نمی‌بیند |
| **اپراتور / درمانگر** | فقط نوبت‌ها و درآمد خودش (`/admin/my`) |

اپراتور باید در بخش «کاربران» به یکی از پرسنل متصل شود تا نوبت‌هایش را ببیند.

#### پکیج جلسات

اگر مشتری یک دوره‌ی چندجلسه‌ای می‌خرد، در پرونده‌اش «فروش پکیج» بزنید:
تعداد جلسات، مبلغ کل و مبلغی که تا الان گرفته‌اید. اقساط بعدی را از همان
کارت ثبت می‌کنید. **جلسات مصرف‌شده شمرده نمی‌شوند، محاسبه می‌شوند** — هر
سابقه‌ی درمانی که به پکیج وصل باشد یک جلسه است، پس اگر جلسه‌ای اشتباه ثبت
و بعد حذف شود، موجودی خودش درست می‌شود.

#### رضایت‌نامه و عکس قبل/بعد

متن رضایت‌نامه‌ها را یک‌بار در `/admin/consents` می‌نویسید (سه نمونه از قبل
هست که باید با نظر مسئول فنی کلینیک بازنویسی شود). در پرونده‌ی مشتری،
منشی متن را نشان می‌دهد و امضا را روی صفحه می‌گیرد. **متن در لحظه‌ی امضا
در سند ثبت می‌شود**، پس ویرایش بعدی قالب، رضایت‌نامه‌های قبلی را عوض نمی‌کند.
برگه‌ی چاپی هم از همان‌جا در دسترس است و خود مشتری هم آن را در حسابش می‌بیند.

عکس‌های قبل/بعدِ پرونده **در `public` ذخیره نمی‌شوند**؛ بیرون از دسترس وب
می‌روند (پیش‌فرض: پوشه‌ی `storage/private`) و فقط با آدرس `/api/files/...`
و پس از بررسی دسترسی سرو می‌شوند: پرسنل پرونده، و خودِ صاحب عکس. اگر هاست
شما فایل‌سیستم ماندگار ندارد، مسیر دیسک ماندگار را در `PRIVATE_UPLOAD_DIR`
بگذارید. این عکس‌ها ربطی به گالری عمومی سایت ندارند.

#### هزینه، انبار و سود واقعی

تا وقتی هزینه‌ای ثبت نشده باشد، گزارش فقط **درآمد** را نشان می‌دهد — و درآمد
سود نیست. سه تکه‌ای که این را درست می‌کند:

**۱. دفتر هزینه** (`/admin/expenses`) — هر چیزی که خرج می‌شود، با دسته‌بندی
(اجاره، حقوق، مواد مصرفی، قبوض، دستگاه، تبلیغات، مالیات، سایر) و بازه‌ی
زمانی. نمودار سهم هر دسته همان‌جاست.

**۲. انبار مواد** (`/admin/inventory`) — ژل، ویال، سرسوزن و هر چیز مصرفی.
برای هر قلم: موجودی، بهای هر واحد، مرز هشدار و تأمین‌کننده. چهار نوع حرکت
ثبت می‌شود: خرید، مصرف، اصلاح شمارش و ضایعات.

دو چیز که خودکار اتفاق می‌افتد:
- **خرید انبار، خودش یک هزینه در دسته‌ی «مواد مصرفی» ثبت می‌کند** — پس لازم
  نیست دو بار وارد کنید، و سود بدون اینکه یادتان برود درست درمی‌آید. این
  هزینه‌ها قفل‌اند و فقط از انبار اصلاح می‌شوند.
- اگر برای خدمتی «مصرف استاندارد» تعریف کرده باشید (مثلاً هر جلسه‌ی لیزر
  ۱٫۵ سی‌سی ژل)، **با ثبت هر جلسه‌ی درمان همان مقدار خودکار از انبار کم
  می‌شود.**

وقتی قلمی به مرز هشدار برسد، در منو نشان می‌خورد، بالای صفحه‌ی انبار هشدار
می‌آید، در گزارش شبانه‌ی مدیر ذکر می‌شود و `npm run doctor` هم می‌گویدش.

**۳. سود، در گزارش‌ها** — درآمد منهای هزینه، با حاشیه‌ی سود. و مهم‌تر:
**سود هر خدمت** = درآمد آن خدمت منهای بهای موادش منهای پورسانت پرسنل. این
همان جدولی است که ممکن است غافلگیرتان کند — گاهی پرفروش‌ترین خدمت
کم‌سودترین است.

> خدمتی که برایش ماده‌ای تعریف نشده، در جدول با برچسب **«بدون مواد»**
> علامت می‌خورد، تا کسی سودِ بدونِ بهای مواد را با سود واقعی اشتباه نگیرد.

#### برنامه‌ی روز (میز پذیرش)

`/admin/day` — به‌جای جدول، یک ستون برای هر پرسنل و بلوک‌های زمانی؛ همان
شکلی که میز پذیرش کار می‌کند. ساعت‌های بیرون از شیفت سایه‌دارند، مرخصی‌ها
دیده می‌شوند و یک خط قرمز نشان می‌دهد الان کجاییم. با کلیک روی هر نوبت،
جزئیات و تغییر وضعیت و شماره‌ی تماس بدون ترک صفحه در دسترس است.

#### گزارش شبانه‌ی پیامکی

هر شب یک پیامک خلاصه به موبایل مدیر:

```
کلینیک زیبایی شهرزاد — گزارش پنجشنبه، ۱۲ شهریور
نوبت: ۴ | انجام: ۲ | نیامد: ۱ | لغو: ۱
دریافتی: ۸۵۰٬۰۰۰ تومان

فردا: ۳ نوبت
```

شماره و روشن/خاموش بودنش از **تنظیمات** قابل تغییر است. روزی که هیچ اتفاقی
نیفتاده باشد پیامکی فرستاده نمی‌شود تا بی‌خود هزینه نشود.

```
0 21 * * *  cd /path/to/app && npm run digest >> /var/log/sharzad.log 2>&1
```

#### نظرسنجی و رضایت مشتری

به‌محض اینکه نوبتی «انجام‌شده» شود، یک پیامک نظرسنجی با لینک یکبارمصرف برای
مشتری می‌رود (اگر نمی‌خواهید خودکار برود، در **تنظیمات ← پیامک نظرسنجی
خودکار** عدد را `0` کنید؛ منشی همیشه می‌تواند از صفحه‌ی نوبت‌ها دستی بفرستد).

مشتری بدون ورود به حساب، امتیاز ۱ تا ۵ می‌دهد و برای هر جنبه — نتیجه‌ی درمان،
برخورد پرسنل، نظافت، زمان انتظار، قیمت و... — می‌گوید راضی بوده یا نه. متن
آزاد هم می‌تواند بنویسد و اجازه‌ی انتشار نظرش را بدهد.

مدیر در `/admin/feedback` نظرها را با فیلترِ «نیاز به رسیدگی / ناراضی‌ها /
همه» می‌بیند، برای هرکدام یادداشت می‌گذارد و «رسیدگی شد» می‌زند. نظر خوبی که
مشتری اجازه‌ی انتشارش را داده، با یک دکمه به بخش نظرات سایت می‌رود.

**چطور تستش کنی؟** در حالت `SMS_PROVIDER="console"` پیامک واقعی نمی‌رود و
لینک نظرسنجی در همان ترمینالی که `npm run dev` اجرا شده چاپ می‌شود. کافی است
وضعیت یک نوبت را «انجام شده» کنی، لینک را از ترمینال برداری و در مرورگر باز
کنی. برای دیدن گزارش‌ها با داده‌ی واقعی هم `npm run demo:feedback` چند ده نظر
نمونه می‌سازد که با `-- --clean` پاک می‌شوند.

دو چیز که خودکار اتفاق می‌افتد:
- **امتیاز ۳ یا کمتر، خودش یک پیگیری در فهرست منشی باز می‌کند** تا نارضایتی
  فقط یک عدد در گزارش نماند و کسی واقعاً زنگ بزند.
- نظر هر مشتری در پرونده‌ی خودش هم ثبت می‌شود، پس دفعه‌ی بعد که می‌آید
  می‌دانید قبلاً از چه چیزی ناراضی بوده.

#### گزارش‌ها و خروجی اکسل

`/admin/reports` — بازه را از میان «این ماه / ماه گذشته / ۳ ماه / ۶ ماه /
امسال / از ابتدا» انتخاب می‌کنید و همه‌ی اعداد همان‌جا حساب می‌شوند.
دکمه‌ی «خروجی اکسل» یک فایل CSV می‌دهد که اکسل فارسی مستقیم بازش می‌کند
(اعداد در فایل خام‌اند تا در اکسل قابل جمع‌زدن باشند).

بخش **رضایت مشتری‌ها** هم همان‌جاست: میانگین امتیاز، نرخ پاسخ، درصد راضی و
ناراضی، درصد کسانی که کلینیک را پیشنهاد می‌کنند، **پرتکرارترین شکایت‌ها و
تعریف‌ها**، و رضایت به تفکیک خدمت و پرسنل (ضعیف‌ترین‌ها اول، چون همان‌ها را
باید درست کرد). همه‌ی این‌ها در خروجی اکسل هم می‌آید.

نکته‌ی مهم: **درآمد فقط از پرداخت‌های ثبت‌شده‌ی موفق شمرده می‌شود.** جلسه‌ای
که منشی مبلغش را ثبت نکرده باشد، در تعداد جلسات می‌آید ولی در درآمد نه.
پرداخت‌های بدون نوبت (مثل قسط پکیج) زیر «بدون نوبت» جدا می‌شوند.
«عدم مراجعه» یعنی نوبتی که وقتش گذشته و هنوز انجام‌شده یا لغو نشده است.

#### کد تخفیف

از `/admin/discounts` کد می‌سازید: درصدی (با سقف تخفیف) یا مبلغ ثابت،
با حداقل مبلغ خرید، بازه‌ی زمانی و سقف تعداد استفاده. **هر مشتری از هر کد
فقط یک بار می‌تواند استفاده کند** و ظرفیت کل هم قابل دور زدن نیست.

کد **هنگام ثبت پرداخت** اعمال می‌شود: منشی در فرم «ثبت پرداخت» کد را وارد
می‌کند، مبلغ همان‌جا کم می‌شود و مصرف کد ثبت می‌گردد. چون پرداخت در همان
لحظه قطعی است، هیچ رزرو نیمه‌کاره‌ای روی کد باقی نمی‌ماند.

#### لیست انتظار

اگر مشتری در فرم رزرو برای روز انتخابی‌اش وقت خالی پیدا نکند، به‌جای
بن‌بست دکمه‌ی «مرا در لیست انتظار بگذارید» می‌بیند و با نام و شماره در
لیست ثبت می‌شود. منشی هم می‌تواند از پرونده‌ی هر مشتری او را اضافه کند.

در `/admin/waitlist` منشی می‌بیند چه کسی منتظر چه خدمتی در چه بازه‌ای است،
با یک دکمه پیامک «وقت خالی شد» می‌فرستد و وضعیت را روی «نوبت گرفت» یا
«منصرف شد» می‌گذارد. وقتی نوبتی لغو می‌شود، همان‌جا به منشی گفته می‌شود
چند نفر منتظر همان خدمت‌اند.

#### حقوق و پورسانت چطور حساب می‌شود؟

برای هر پرسنل «حقوق پایه‌ی ماهانه» و «درصد پورسانت» تعریف می‌کنید
(و در صورت نیاز درصد اختصاصی برای هر خدمت).

مبنای پورسانت هر جلسه:
1. اگر برای آن نوبت **پرداخت ثبت شده باشد** → همان مبلغ
2. اگر ثبت نشده باشد → قیمت پایه‌ی خدمت، با برچسب **«تخمینی»**

پس برای محاسبه‌ی دقیق، منشی باید بعد از هر جلسه از صفحه‌ی نوبت‌ها مبلغ
دریافتی را ثبت کند. فیش ماهانه که صادر شد، مبالغش قفل می‌شود و تغییرات
بعدی نوبت‌ها آن را عوض نمی‌کند.

## پیامک، ایمیل و درگاه پرداخت

هر سه اختیاری‌اند و سایت بدون آن‌ها کامل کار می‌کند، اما تا تنظیم نشوند
قابلیت‌های وابسته به آن‌ها غیرفعال می‌مانند.

### پیامک (ملی پیامک یا کاوه‌نگار)

```env
SMS_PROVIDER="kavenegar"
KAVENEGAR_API_KEY="..."
KAVENEGAR_SENDER="..."
KAVENEGAR_OTP_TEMPLATE="نام الگوی تأییدشده در پنل کاوه‌نگار"
```

با `SMS_PROVIDER="console"` (پیش‌فرض) پیام‌ها فقط در ترمینال چاپ می‌شوند —
برای توسعه عالی است و هزینه‌ای ندارد.

> ⚠️ **مهم:** اگر سایت را منتشر کنید و پیامک تنظیم نشده باشد، **مشتریان
> نمی‌توانند وارد حساب شوند**. سایت این را عمداً مسدود می‌کند تا کد ورود
> روی صفحه لو نرود. در پنل مدیریت هم هشدار قرمز نشان داده می‌شود.

پیامک‌های خودکار: ثبت نوبت، تأیید، لغو، یادآوری و کد ورود.

**یادآوری روزانه** را با cron روی سرور تنظیم کنید:

```bash
0 10 * * *  cd /path/to/app && npm run reminders >> /var/log/sharzad.log 2>&1
```

### ایمیل

```env
SMTP_HOST="..."
SMTP_PORT="587"
SMTP_USER="..."
SMTP_PASS="..."
SMTP_FROM="کلینیک شهرزاد <no-reply@sharzadclinic.ir>"
```

اگر خالی بماند ایمیل‌ها فقط در ترمینال چاپ می‌شوند.

### درگاه پرداخت (زرین‌پال)

```env
ZARINPAL_MERCHANT_ID="شناسه‌ی پذیرنده از پنل زرین‌پال"
ZARINPAL_SANDBOX="true"   # برای تست بدون پول واقعی
```

با `ZARINPAL_SANDBOX="true"` می‌توانید کل مسیر پرداخت را بدون تراکنش واقعی
تست کنید. تا وقتی شناسه وارد نشود، دکمه‌ی پرداخت به مشتری نمایش داده نمی‌شود.

درصد بیعانه از **پنل → تنظیمات → درصد بیعانه‌ی آنلاین** قابل تغییر است.

## پشتیبان‌گیری

سه راه، و هر سه به یک جا می‌رسند:

**۱. خود مدیر، از پنل.** `/admin/backup` — یک دکمه، و فایل zip روی همان
دستگاه دانلود می‌شود. اگر با گوشی باز کرده باشد، فایل در «دانلودها»ی گوشی
می‌نشیند و می‌تواند برای خودش در تلگرام بفرستد. دو گزینه دارد: کامل (با
عکس‌های پرونده) و سبک (فقط اطلاعات، سریع).

**۲. خودکار روی سرور.** یک کرون شبانه که ۱۴ نسخه‌ی آخر را نگه می‌دارد:

```
0 3 * * *  cd /path/to/app && npm run backup >> /var/log/sharzad.log 2>&1
```

نسخه‌های سرور در همان صفحه‌ی پنل فهرست می‌شوند و از آن‌جا هم قابل دانلودند.
اگر بیش از یک روز پشتیبان گرفته نشده باشد، بالای صفحه هشدار زرد می‌آید و
`npm run doctor` هم تذکر می‌دهد.

**۳. بازگردانی.**

```bash
npm run restore -- storage/backups/sharzad-backup-1405-06-12-0300.zip
```

بدون `--yes` فقط گزارش می‌دهد داخل فایل چیست و چه چیزی قرار است جایگزین
شود. با `--yes` واقعاً بازمی‌گرداند.

داخل فایل چیست: یک `manifest.json`، یک فایل JSON برای هر جدول (به ترتیب
وابستگی، تا کلیدهای خارجی موقع بازگردانی نشکنند) و پوشه‌ی عکس‌های عمومی و
خصوصی. چون به `pg_dump` وابسته نیست، روی هر هاستی کار می‌کند.

> ⚠️ فایل پشتیبان **همه‌ی پرونده‌های پزشکی و عکس‌های مراجعین** را دارد.
> فقط مدیر کل به آن دسترسی دارد (منشی و اپراتور حتی لینکش را نمی‌بینند)،
> و جایی که نگهش می‌دارید هم باید همان‌قدر امن باشد.

## مهاجرت داده از اپلیکیشن قدیمی (SQL Server)

داده‌های اپ قبلی (مشتریان، نوبت‌ها، سوابق درمان، پرداخت‌ها) با یک اسکریپت اختصاصی منتقل می‌شوند.

### گام ۱ — اتصال

مقادیر `LEGACY_MSSQL_*` را در `.env` پر کن:

```env
LEGACY_MSSQL_SERVER="192.168.1.10"
LEGACY_MSSQL_DATABASE="ClinicOld"
LEGACY_MSSQL_USER="sa"
LEGACY_MSSQL_PASSWORD="..."
```

### گام ۲ — دیدن ساختار دیتابیس قدیمی

```bash
npm run import:legacy -- --inspect
```

همه‌ی جدول‌ها، ستون‌ها و تعداد رکوردها چاپ می‌شود.

### گام ۳ — تنظیم نگاشت

بر اساس خروجی بالا، فایل **`scripts/legacy-mapping.ts`** را ویرایش کن.
تنها فایلی است که باید دست بزنی؛ نام جدول‌ها و ستون‌ها آن‌جاست.
تبدیل مقادیر (جنسیت، وضعیت نوبت، روش پرداخت) هم در همان فایل قابل تنظیم است.

> اگر مبالغ در اپ قدیمی به **ریال** ذخیره شده‌اند، `AMOUNT_DIVISOR` را روی `10` بگذار.

### گام ۴ — تست بدون نوشتن

```bash
npm run import:legacy -- --dry-run
```

### گام ۵ — اجرای واقعی

```bash
npm run import:legacy
```

```bash
# فقط بخش‌های مشخص
npm run import:legacy -- --only=customers,payments
```

**نکات مهم**

- مهاجرت **idempotent** است: هر رکورد با `legacyId` یکتا ثبت می‌شود، پس اجرای
  چندباره رکورد تکراری نمی‌سازد و فقط به‌روزرسانی می‌کند.
- مشتری‌هایی که شماره‌ی موبایل نامعتبر یا تکراری دارند با شناسه‌ی `LEGACY-<id>`
  ثبت می‌شوند تا هیچ رکوردی از دست نرود؛ بعداً در پنل قابل اصلاح‌اند.
- خدمات منتقل‌شده در دسته‌ی «منتقل‌شده از اپ قبلی» و **غیرفعال** می‌نشینند
  تا با محتوای سایت قاطی نشوند. خودت بررسی و فعالشان کن.
- ترتیب اجرا خودکار رعایت می‌شود: خدمات → مشتریان → نوبت‌ها → سوابق → پرداخت‌ها.

## انتشار (Publish)

پروژه به هیچ سرویسی قفل نیست. `DATABASE_URL` و `AUTH_SECRET` تنها چیزی است که هر جا لازم داری.

> `AUTH_SECRET` را حتماً عوض کن: `openssl rand -base64 32`

### لیارا / ابرآروان / هر PaaS ایرانی

```bash
# یک دیتابیس PostgreSQL از پنل سرویس بساز و connection string را بگیر
liara deploy   # فایل liara.json از قبل آماده است
```

متغیرهای محیطی روی پنل سرویس: `DATABASE_URL`، `AUTH_SECRET`، `NEXT_PUBLIC_SITE_URL`.
بعد از اولین دیپلوی یک بار `npx prisma migrate deploy` را روی سرور اجرا کن.

### VPS با داکر

```bash
docker build -t sharzad-clinic .
docker run -d -p 3000:3000 --env-file .env --restart unless-stopped sharzad-clinic
```

### Vercel

ریپو را وصل کن و یک PostgreSQL خارجی (Neon / Supabase) بده.
⚠️ Vercel روی IP ایران بلاک است؛ برای مخاطب ایرانی گزینه‌ی خوبی نیست.

## نکات فنی

- **تکنولوژی:** Next.js 15 (App Router) · TypeScript · Tailwind CSS 4 · Prisma · PostgreSQL
- **منطقه‌ی زمانی:** سرور روی `Asia/Tehran` قفل شده تا محاسبات نوبت قطعی باشد.
- **رزرو هم‌زمان:** پیش از ثبت نهایی، اسلات دوباره سمت سرور اعتبارسنجی می‌شود؛
  اگر بین انتخاب و ثبت کسی همان ساعت را گرفته باشد، خطای مشخص برمی‌گردد.
- **احراز هویت:** JWT امضاشده در کوکی `httpOnly` + محافظت مسیرها در middleware.
- **فونت:** Vazirmatn به‌صورت لوکال (بدون CDN خارجی) — سایت آفلاین هم درست نمایش داده می‌شود.
